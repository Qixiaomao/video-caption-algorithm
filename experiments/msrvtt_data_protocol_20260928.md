## Media and frame transformation

`scripts/prepare_msrvtt_full_20260928.py` reads every MP4 member through `zipfile`, verifies its CRC while extracting, computes a local SHA-256, and performs a full sequential OpenCV decode. It samples eight indices `round(i*(N-1)/7)` for `i=0..7` from the actual decoded frame count. It applies the existing MSVD 224×224 aspect-preserving black letterbox and JPEG quality 95. Short videos with 1–7 decoded frames would use deterministic repeated indices; zero-frame or unreadable media fails the full-data gate. No video is silently excluded. Every output video and JPEG is written under the new run directory, with per-ID evidence in `media_audit.jsonl` and the complete `manifest.json`.

`scripts/finalize_msrvtt_data_20260928.py` rereads the source ZIP hash and every local media/frame SHA-256, reopens every 224×224 RGB JPEG, checks annotation and split coverage, and groups exact media and complete eight-frame hash duplicates across splits. It produced `data_audit.json` and `resource_estimate.json`. The media audit is **PASS**: 10,000/10,000 full decodes and 80,000/80,000 frames, zero failures, zero metadata frame-count mismatches, minimum decoded length 60 frames, zero exact duplicate media or eight-frame sets, and zero cross-split exact media/frame matches. This is an exact-hash screen; it does not claim to detect every semantically similar but differently encoded clip. The 3,127 lowercased whitespace-normalized caption strings shared across splits are disclosed as text overlap.

The first extraction/decode/frame pass took 1,757.4 s. The second pass, measured from the last media-journal write to the `data_audit.json` write, took another 1,099.8 s. The ZIP occupies 6,552,768,292 B, extracted MP4s 6,721,784,101 B, and eight-frame JPEGs 1,238,987,819 B. These are measured bytes, not extrapolations. The cache job adds its measured time and disk use to `resource_estimate_complete.json`.

## Caption and feature-cache policy

`train_val_caption_token_audit.json` checks all 130,260 train and 9,940 val references with the local original GPT-2 tokenizer. Maximum lengths are 74 and 52 tokens respectively. The old MSVD `max_len=64` would truncate train video141 caption ID 130059; MSR-VTT uses **96 positions including the kept EOS** for both arms and all seeds. Empty captions, embedded EOS, and any caption needing 96 or more positions fail before formal training. The training adapter must assert the exact 6,513/497 IDs before using the shared dataloader, because that legacy loader otherwise drops missing-frame records.

The cache job `scripts/cache_msrvtt_train_val_20260928.py` built only train/val raw pooled 768-dimensional frozen ViT-B/16 features. Every batch compared `encoder(video)` with `encoder.proj(raw_cache_feature)`, checked finite outputs and original split order. The measured maximum absolute error was **0.0** in both splits; cache shapes were **[6513, 768]** and **[497, 768]**. The job took **5,999.3 s** and peaked at **1,060 MiB reserved GPU memory**. The train and val cache SHA-256 values are `e71d5680fe93747ab7e911532d5a1109c21fd59b737ec20aa5f77272a06ae339` and `127de7229bc0c3f1d47ace2a0ab60b364858f4b328bc90b4da8168b10b396d4c`. ## Evaluation isolation and failure rule

The test2990 split is used here only for annotation, media and frame integrity. No test ViT feature, prediction, caption score or retrieval score is computed at this gate. The fixed future decode, caption metrics and matched-captioning-test2990 retrieval definition are in `experiments/msrvtt_test_eval_config_20260928.json`. This is not the separate MSR-VTT 1K retrieval benchmark.

If a source or output media item later proves invalid, retain its ID, log and source hash; retry the same pinned source without silently deleting it. A persistent invalid clip keeps the standard full-split gate FAIL. A reduced subset requires its own separately named supplementary protocol and cannot count as full MSR-VTT replication.
